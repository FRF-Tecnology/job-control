# Applyer · Plano de implementação do primeiro acesso

> Para quem for implementar: use `superpowers:subagent-driven-development` ou `superpowers:executing-plans`. Cada caixa abaixo tem uma entrega que pode ser demonstrada separadamente. Esta entrega é o plano.

**Objetivo:** uma pessoa que abre o Applyer pela primeira vez conecta sua IA, anexa um currículo real, confirma que vagas procura e chega ao Radar com o perfil salvo e pronto para buscar. Se fechar o aplicativo no caminho, continua de onde parou.

**Arquitetura:** o aplicativo desktop é a fonte de verdade. React apresenta o fluxo do protótipo; a API Go confirma conexão, grava o PDF e o progresso no armazenamento local e entrega o perfil à busca existente. A janela do Wails continua mostrando o Applyer; sites externos abrem no navegador padrão do sistema.

**Tecnologias:** Wails v3.1.0, React/TypeScript, Go, SQLite, arquivos locais de currículo, cofre do sistema e Playwright. Sem serviço de conta, novo provedor de IA ou extensão de navegador para completar o primeiro acesso.

**Referência:** [main verificada, PR #156](https://github.com/FRF-Tecnology/job-control/commit/ddc2d6d96eefb10c32bd424812793a910e82bce5), 12/11/2026. A árvore do checkout inspecionado coincide com a da main. Referência visual e interativa: o artefato `Applyer-prototipo-navegavel.html` já entregue, telas “Primeiro acesso”, “Perfil e IA” e “Radar de vagas”.

**Restrições:** Windows e macOS; teclado, foco visível e movimento reduzido; português do Brasil. Sem currículo de exemplo, conta fictícia, vagas semeadas ou credencial de demonstração no app. Chaves somente no cofre; nenhum segredo, texto integral do CV ou caminho de origem em logs. Nenhuma candidatura disparada pelo onboarding.

## Começar pelo menor percurso que prova valor

**Teste de base, possível hoje:** num ambiente de teste vazio, usar uma conexão Claude já autorizada, passar pelo teste de conexão, escolher um PDF fictício válido pelo seletor, preencher os critérios manualmente e salvar. O desktop atual deve gravar uma cópia do PDF e o perfil e abrir **Triagem**. Não é necessário extrair sugestões com IA para provar a importação. Com a integração e as fontes disponíveis, hoje essa última ação também inicia a busca.

**Primeira fatia a entregar:** fazer esse mesmo percurso desembocar no **Radar de vagas**, com uma ação principal, **Buscar vagas**, e o perfil que acabou de ser salvo. A pessoa deve conseguir distinguir “perfil pronto” de “busca concluída”. Não esperar por multiperfil, migração do executor ou por um anúncio externo disponível para testar esse primeiro marco.

| O que queremos provar | Dependência que pode impedir o teste |
|---|---|
| Seleção, gravação, reabertura e navegação | Pasta de testes gravável e build do app. Em CI, usar PDF gerado e provedor controlado. Isso comprova o armazenamento, não uma autenticação Claude real. |
| Selo “Claude conectado” e volta do login | Uma conta de teste habilitada, rede e CLI Claude nativa compatível para a via assinatura; na via API, chave e modelo autorizados. Sem isso o aceite real da conexão fica pendente, mesmo que o E2E passe. |
| Primeira busca com fonte e classificação reais | Pelo menos uma fonte alcançável e provedor apto a avaliar. Uma consulta sem vagas pode ser legítima; usar anúncios controlados para verificar a ordenação A/B/C e uma rodada real separada para verificar a integração. |
| Navegador padrão e retorno em cada sistema | Build empacotado em Windows e macOS, navegador padrão definido e máquina de teste para cada um. Chromium headless sozinho não comprova a troca entre aplicativos. |

**Evidência desta revisão:** percorremos o HTML em Chromium sem chamadas de rede e executamos o [E2E do app](https://github.com/FRF-Tecnology/job-control/blob/ddc2d6d96eefb10c32bd424812793a910e82bce5/app/frontend/e2e/primeiro-acesso.setup.ts) com a API Go, SQLite vazio e cofre em memória: **1 teste passou**. Ele comparou os bytes do PDF salvo e releu cargo, stack, filtros e faixa USD 4.000–6.000. Estado da IA, teste do provedor, sugestões e busca eram respostas controladas. O teste usa o motor web com a API local; não demonstra o seletor nativo nos dois sistemas, login real, nem retorno do navegador do sistema.

## Ordem de implementação

Nos caminhos abaixo, `ui/` significa `app/frontend/src/`. Os endpoints são da API local `/api/v1`. Para cada fatia: reproduzir primeiro a falha com o teste indicado, implementar, rodar novamente e anexar evidência do aceite; um PR por fatia.

### 1. Fechar o caminho feliz: duas telas → perfil salvo → Radar

**Arquivos:** `ui/App.tsx`, `ui/telas/PrimeiroAcesso.tsx`, `ConexaoOnboarding.tsx`, `BuscaDoPerfil.tsx`, `Triagem.tsx` (estes quatro em `ui/telas/`), `ui/estilo/primeiro-acesso.css`; criar `ui/telas/Radar.tsx`. Referência visual: `work/prototipo-navegavel/profile.js`, `shell.js`, `radar.js`.

- [ ] Tela **1 · Sua IA e seu currículo**: conectar e anexar na mesma tela, em qualquer ordem. Resolver cada requisito no próprio cartão. Para continuar, exigir um PDF válido e um teste de provedor bem-sucedido; se o provedor falhar, manter o arquivo e oferecer “Tentar novamente”. Reutilizar o teste real da conexão existente. Para a primeira fatia, começar com credencial já autorizada.
- [ ] Tela **2 · Que vagas você procura?**: deixar a pessoa revisar e corrigir os campos ali mesmo. Cargo, nível, stack principal, mercado, modelo de trabalho e inglês alimentam o contrato de busca atual. Stack secundária, exclusões e faixa mensal USD/BRL/EUR ficam opcionais. Não exigir nome de exibição para buscar, nem adivinhar salário, mercado ou exclusões pelo currículo. As sugestões nunca substituem edições da pessoa. Sem terceira tela que apenas repita o formulário.
- [ ] Usar `POST /onboarding` existente como base nesta fatia. Após confirmação e releitura de `/estado`, direcionar a `#/radar`. “Concluir perfil” salva; **Buscar vagas** inicia uma única busca no Radar. Desacoplar o gatilho preso a `#/triagem?buscar=1`; endereços antigos de Triagem continuam chegando ao equivalente. Preservar as instalações já concluídas.
- [ ] **Aceite:** instalação limpa → conta de teste já autorizada → anexar PDF → preencher/revisar → concluir. O Radar abre com cargo e critérios registrados, zero vagas fictícias e botão Buscar vagas. Reabrir após concluir volta à principal, sem repetir o assistente. Verificar em `app/frontend/e2e/primeiro-acesso.setup.ts` e em um build desktop. O fechamento **no meio** é o aceite da fatia 2.

### 2. Salvar o progresso e o PDF no momento certo

**Arquivos:** `internal/api/{http,onboarding,onboarding_sugestoes}.go`, `internal/armazem/onboarding.go`, `internal/curriculos/{importacao,texto}.go`, `api/openapi.yaml`, `ui/telas/{PrimeiroAcesso,Perfil}.tsx`, `ui/app/contexto.ts`. Criar `internal/armazem/onboarding_rascunho.go` e `ui/telas/CurriculoDoPerfil.tsx`. Arte original: [curriculo-verificado.svg](https://github.com/FRF-Tecnology/job-control/blob/ddc2d6d96eefb10c32bd424812793a910e82bce5/site/artes/curriculo-verificado.svg); usar o mesmo SVG no cartão e no resumo.

- [ ] Acrescentar estado de rascunho versionado no SQLite, separado do marcador legado: etapa, revisão, campos editados, referência opaca ao CV, nome de apresentação sem caminho e tentativa externa pendente. Atualizar ao sair de um campo e após uma pausa curta ao digitar; ao avançar, aguardar a gravação pendente. Indicar “Salvando…” e só então “Salvo neste computador”. Em falha, manter a edição e oferecer nova tentativa. Impedir uma resposta atrasada de sobrescrever uma edição mais nova.
- [ ] Contrato proposto: `GET /onboarding/rascunho` restaura; `PATCH /onboarding/rascunho` recebe os campos alterados e a revisão esperada; `PUT /onboarding/curriculo` recebe o PDF e devolve `{arquivoId,nomeExibicao,tamanho, revisao}` **após** gravação; `DELETE /onboarding/curriculo` remove o vínculo do rascunho. Manter as proteções da janela e o cabeçalho `X-Applyer-Onboarding` nas mutações; referência aceita somente pelo app e para o perfil local correspondente. Conflito de revisão → recarregar o rascunho antes de salvar outra vez.
- [ ] Manter o seletor nativo atual, acessível por teclado. Exibir **“Selecionado: currículo.pdf” → “Salvando…” → “Currículo salvo neste perfil”**. Se a pessoa cancelar a troca, escolher um arquivo inválido, exceder o limite ou faltar espaço, preservar o PDF anterior. Só substituir o vínculo após confirmar a nova cópia. Reabrir mostra o nome original, mesmo se o arquivo de Downloads mudou de lugar.
- [ ] Reutilizar a importação e recuperação transacional do Go. A extração e a conclusão passam a usar o mesmo `arquivoId` do rascunho, sem segundo upload. Não gravar base64 no SQLite ou no armazenamento do navegador. Ajustar a migração para que um PDF de rascunho não transforme uma instalação interrompida em “concluída”; manter atualizações de usuários antigos e a remoção de dados. Finalização repetida com a mesma revisão já salva deve retornar o mesmo perfil.
- [ ] Na leitura inicial, aplicar uma ordem inequívoca: **perfil concluído → Radar; rascunho em andamento → etapa recuperada; instalação reconhecida como legado → fluxo existente; instalação nova → etapa 1**. Alterar a conclusão para aceitar `{arquivoId, revisao, perfil}` sem quebrar de imediato o contrato atual de PDF + perfil. Confirmar no backend a referência ao arquivo e a verificação válida do provedor antes de promover o rascunho; o React não decide que o perfil está pronto.
- [ ] **Aceite:** após “Currículo salvo”, fechar e reabrir **o processo**; arquivo, etapa e campos já salvos reaparecem. Testar troca inválida, PDF sem camada de texto (salvo, com preenchimento manual), falha de disco, fechamento entre gravação e confirmação e duplo clique em concluir. Um PDF referenciado, sem perfil duplicado nem documento órfão. Ampliar `internal/{api,armazem}/onboarding_test.go` e `ui/telas/primeiro-acesso.test.tsx`.

### 4. Conectar o Claude e reconhecer a volta da autenticação

**Arquivos:** `ui/telas/{ConexaoOnboarding,ConectarIA,Hoje}.tsx`, `ui/App.tsx`, `ui/estilo/conexao-onboarding.css`, `internal/{ia/cli,api/ia}.go`, `api/openapi.yaml`; criar `ui/telas/StatusConexaoIA.tsx`. Usar [site/marcas/claude.svg](https://github.com/FRF-Tecnology/job-control/blob/ddc2d6d96eefb10c32bd424812793a910e82bce5/site/marcas/claude.svg) no seletor, no cartão e no resumo lateral.

- [ ] Um estado compartilhado para onboarding, Perfil e menu: **Não conectado → Aguardando login → Verificando → Claude conectado** ou **Falha + ação**. Configuração gravada, CLI instalada, chave no cofre, abertura do navegador e retorno de foco não autorizam o selo. Só publicar o sucesso quando `POST /ia/testar` devolver `ok: true` para a configuração atual. Registrar última confirmação, invalidar ao trocar provedor, credencial, modelo ou destino e diante de falha de autenticação. Em nova sessão, “Verificando” ou “Última verificação…” até reconfirmar; não consumir cota a cada foco.
- [ ] **Assinatura:** salvar tentativa e etapa **antes** de iniciar o fluxo oficial `claude auth login`; quem controla a autenticação no navegador é a CLI, não o Applyer. Usar o executável nativo aceito no projeto e validar, nos dois sistemas, se a versão suportada funciona ao ser iniciada pelo desktop. Se exigir terminal interativo, mostrar o comando copiável e manter **“Já entrei · verificar”** no mesmo cartão. CLI ausente ou incompatível → “Como instalar” no navegador padrão, com alternativa de chave.
- [ ] **Volta ao app:** enquanto existir tentativa, ao recuperar foco, reabrir o app ou clicar em “Já entrei”, consultar o estado atualizado da CLI sem reutilizar os 45 s de cache. Distinguir login negativo de status desconhecido. Após login detectado, verificar de fato com `/ia/testar`; se a CLI não oferecer status confiável, permitir esse teste explícito, sem alegar conexão antes do resultado. Sem protocolo de retorno próprio, token na URL ou leitura de cookies. Cancelar, fechar a aba ou expirar o tempo deixa o PDF e os campos intactos. Ignorar resposta de tentativa anterior.
- [ ] **Chave Anthropic:** reutilizar a configuração e o cofre existentes; após gravar, executar o mesmo teste. Separar “Credencial recusada” (trocar chave/refazer login), “Sem rede” (tentar novamente) e “CLI não encontrada” (instalar). Uma ação por recuperação. Para sugestões do CV, manter o aviso sobre o envio do texto profissional ao provedor e a alternativa manual; não enviar o PDF no teste de conexão.
- [ ] **Aceite:** em máquina sem Claude, nenhum selo verde. Com login cancelado, chave inválida, indisponibilidade ou simples alternância de janela, continua sem selo. Com retorno válido, a logo e “Claude conectado” aparecem em todos os pontos, uma única verificação é feita por tentativa e a pessoa continua na etapa atual sem perder o PDF. Testes: `ui/telas/{conexao-onboarding,conectarIA}.test.tsx`, `internal/api/ia_test.go` e autenticação com conta de teste. [Referência oficial da CLI: login e status](https://code.claude.com/docs/en/cli-reference).

### 5. Fazer a triagem do perfil chegar ao Radar e alimentar uma busca real

**Arquivos:** `ui/telas/{PrimeiroAcesso,Perfil,Radar,BuscaDoPerfil,Triagem}.tsx`, `ui/App.tsx`, `internal/api/{onboarding_sugestoes,busca}.go`, `internal/triagem/busca.go`, `internal/busca/fontes.go`.

- [ ] **Antes de concluir:** a triagem do **perfil** é revisar os dados profissionais obtidos do CV e informar só preferências que ele não comprova. Disparar sugestões apenas pela ação da pessoa; mostrar evidência quando disponível. Se a extração falhar, “Preencher manualmente” leva ao mesmo formulário. Não repetir perguntas ao entrar em Perfil. Reutilizar identidade Applyer, logo com ponto, arte original, contraste/foco e transições curtas do protótipo; respeitar movimento reduzido.
- [ ] **Depois de concluir:** a triagem **das vagas** só existe após a busca. O Radar exibe cargo, filtros e currículo salvos no backend. Não duplicar Hoje, Triagem e Radar como três caminhos para a mesma primeira busca. Reaproveitar `BuscaDoPerfil`, fontes e ordenação já implementadas. Exibir “Buscando e avaliando”, A/B/C em ordem, pendências retomáveis, “Nenhuma vaga com estes critérios” ou “Não foi possível consultar a fonte”, conforme a resposta. Uma falha de rede não desfaz o onboarding. Voltar à tela ou recarregar não deve repetir a chamada.
- [ ] **Aceite:** configurar, por exemplo, Java Engineer, nível pleno, remoto, USD 4.000–6.000 e exclusão de presencial; editar uma sugestão e concluir. Conferir o mesmo perfil na tela principal, em Perfil e na requisição de busca pelo estado persistido. Com anúncios controlados, excluir os incompatíveis explícitos e mostrar A antes de B e C; dados de salário ausentes não devem ser anunciados como incompatibilidade comprovada. Em instalação limpa, nenhuma vaga antes do primeiro clique. Testar também sem resultados, fonte indisponível e sessão da IA expirada.
- [ ] **Limite desta entrega:** produzir o **primeiro perfil real**. O protótipo já alterna perfis de Java e IA; o armazenamento de produção ainda tem um perfil e uma avaliação por vaga. Reservar a associação ao perfil no contrato de rascunho; não exibir seletor para um segundo perfil até existir armazenamento independente. Isso não condiciona o teste do primeiro acesso.

Migrar pendentes para retomada manual; não voltar a executar itens antigos. `internal/api/dados.go`: “sair das plataformas” não desconecta sessões do navegador pessoal. - [ ] **Aceite:** no Windows e no Mac, com e sem a configuração de envio experimental, abrir vaga, sair para a plataforma, voltar, cancelar, reabrir e confirmar manualmente. Nenhum Chrome/Edge privado, janela “Ao vivo”, captura ou solicitação à rota antiga nesse fluxo. | 1. Instalação limpa | Abrir sem dados, navegar pelo teclado; selecionar um PDF real no seletor, conectar Claude e revisar. Repetir invertendo a ordem. | Sem dados de exemplo; logo e arte corretas; nome e confirmação de arquivo salvo; “Claude conectado” só após resposta válida. Cada dado é informado uma vez. |
| 2. Interrupção | Fechar após salvar o CV, durante o login externo e após editar um critério já marcado como salvo. Reabrir o processo; no login, experimentar cancelar e depois concluir. | Restaura a etapa útil, o arquivo e os campos. Revalida a tentativa de conexão quando necessário. Não obriga a reanexar, não inventa conexão e não duplica o perfil. |
| 3. Chegada à principal | Concluir; testar também duplo clique, fechamento logo após salvar e nova abertura. No Radar, entrar em Perfil e voltar; iniciar a primeira busca. | Abre o Radar do perfil certo. Mesmos dados que foram revisados. Só uma gravação e uma busca por intenção. A/B/C com dados de teste; zero resultados ou falha com próximo passo explícito. Nada enviado em nome da pessoa. |
| 4. Falha recuperável | PDF inválido, PDF sem camada de texto, falha de gravação, provedor offline, sessão expirada, fonte indisponível. | Mensagem distingue seleção, gravação, leitura, autenticação e busca. Oferece a ação adequada e conserva o progresso confirmado. Nenhuma nota ou sugestão fabricada. |
| 5. Navegador externo | Mudar o navegador padrão; abrir ajuda, login e vaga. Fechar a aba, voltar sem autenticar e depois retornar após autenticar. Fazer o mesmo numa candidatura sem callback. | Abre no navegador escolhido. Claude só avança com prova da integração. Site de emprego fica pendente até confirmação humana; eventos não se duplicam. |
| 6. Atualização de uma instalação existente | Abrir cópia de teste de banco anterior com perfil concluído e vagas; repetir com um novo rascunho incompleto e PDF já salvo. | Primeiro caso entra na principal preservando histórico; segundo retoma o onboarding. Um PDF salvo sozinho não pula as etapas restantes. |

**Portão de liberação:** executar os testes Go de armazenamento, currículo, API e triagem (`go test ./internal/armazem ./internal/curriculos ./internal/api ./internal/triagem`), os testes React e o Playwright dedicado (`npm test`, `npm run build`, `npx playwright test --project=primeiro-acesso`, em `app/frontend`). Manter um E2E determinístico para regressões, um percurso de autenticação real e uma abertura no navegador padrão em **cada** sistema. O primeiro não substitui os dois últimos. Registrar evidência em perfil de teste, inclusive da retomada após fechar o processo.
